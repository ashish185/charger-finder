# Chargefinder — CPO Portal API Contracts

Derived from PRD v3, Sections 8 (CPO Flows), 11 (CPO Portal Strategy), 12 (Accountability Model), 15 (Integration Model). Covers only CPO-side/portal APIs — driver-app APIs are out of scope here.

**Base URL:** `/api/v1/cpo`
**Auth:** All endpoints (except registration/login) require `Authorization: Bearer <access_token>`, scoped to the authenticated CPO's own stations. Standard envelope: `{ "success": bool, "data": {...}, "error": {...} }`.

---

## 1. CPO Registration & Login

_(PRD Flow 1: only verified CPOs can access the portal)_

### 1.1 Register CPO

`POST /auth/register`

```json
// Request
{
  "companyName": "string",
  "contactName": "string",
  "email": "string",
  "phone": "string",
  "gstNumber": "string",
  "businessType": "individual | company | mall | hotel | campus | parking_operator",
  "city": "string"
}

// Response 201
{
  "success": true,
  "data": {
    "cpoId": "cpo_uuid",
    "status": "pending_verification",
    "createdAt": "2026-08-06T10:00:00Z"
  }
}
```

### 1.2 Submit Verification Documents

`POST /auth/{cpoId}/verification-documents`

```json
// Request (multipart/form-data)
{
  "documentType": "gst_certificate | business_license | pan | electricity_agreement",
  "file": "binary"
}

// Response 202
{
  "success": true,
  "data": { "documentId": "doc_uuid", "status": "under_review" }
}
```

### 1.3 Verification Status

`GET /auth/{cpoId}/verification-status`

```json
// Response 200
{
  "success": true,
  "data": {
    "cpoId": "cpo_uuid",
    "status": "pending_verification | verified | rejected",
    "reason": "string | null",
    "verifiedAt": "timestamp | null"
  }
}
```
